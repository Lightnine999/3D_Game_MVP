## 1. 배경과 목적

### 1.1 배경
- 3인 비개발자가 AI 도구(Claude, OpenAI)와 무료 에셋으로 Google Play에 출시 가능한 3D 게임을 만들 수 있는지 검증한다.(결제 시스템을 토스페이먼츠로도 테스트해본다.)
- 레퍼런스 Into the Dead는 "어둠 속에서 좀비가 나타나는 긴장감"이 핵심 재미다. 이 재미는 사실적인 그래픽이 아니라 **안개·조명·사운드·등장 타이밍**에서 나오므로, 로우폴리 에셋으로도 재현할 수 있다고 판단했다.

### 1.2 MVP 목적
마감(10/2 10:00)까지 아래 4가지를 완성한다.

| # | 범위 | 내용 |
|---|---|---|
| 1 | **게임** | 스테이지 1개를 완성도 있게 (4.1 - 4.10) |
| 2 | **회원가입·회원 관리** | 게스트로 바로 플레이, 이메일+비밀번호 가입, 닉네임 변경·비밀번호 재설정·로그아웃·탈퇴 (4.11) |

### 2.1 개발 팀 (3인, 기능 단위 분담)

**분담 원칙: "기능 하나 = 한 사람"** — 한 기능의 장면(.tscn)·스크립트(.gd)·DB 표·서버 함수·테스트를 한 사람이 끝까지 맡는다. 같은 파일을 두 사람이 동시에 고치지 않게 하는 것이 업무량을 1/3씩 맞추는 것보다 중요하다. 파일 단위 소유권은 TECH_SPEC 13.1, 담당 간 연결 규칙은 TECH_SPEC 13.3.

| 역할 | 한 줄 정의 | 맡는 기능 | 안 맡는 것 |
|---|---|---|---|
| **A. 월드·비주얼** | **보이는 세계**를 만든다 | 콘셉트, 모델, 애니메이션, 지형·스테이지, 안개·조명, 원경(깊이감), 이펙트, 사운드, 비주얼 다듬기 | 서비스 기능 전부 |
| **B. 게임플레이** | 게임이 **돌아가게** 만든다 | 플레이어·카메라, 좀비 AI, 무기·보급·칼, 장애물, 스포너, 미션, **테스트 모드(테스트 패널)**, 밸런스, 성능 | 서버, UI 화면 |
| **C. 서비스·UI·배포** | **게임 밖 서비스**와 화면을 만들고 내보낸다 | UI 전체, 회원가입·회원 관리, 토스 테스트 결제, 문의·제보 채팅, 관리자, 보안 점검, 빌드·배포, **조립(머지) 담당** | 게임플레이 |

- 세 사람 모두 Claude로 바이브 코딩한다. C는 서버·UI 코드 비중이 커서 Claude 세션을 2개 띄워 병렬로 진행한다.
- 기다리지 않기 위해 **가짜 부품**(회색 모델, 가짜 게임 신호)으로 먼저 작업하고, 진짜가 오면 같은 이름으로 갈아 끼운다 (TECH_SPEC 13.3).
- 실제 담당자 이름은 `WORK_UNITS.md` 1.1에 적는다.

## 3. 게임 개요

### 3.1 한 줄 소개
좀비가 가득한 안개 낀 노을 들판을 1인칭으로 달려 요새 정문까지 살아남아라.

### 3.2 핵심 게임 루프
```
스테이지 카드에서 미션 3개 확인
  → 달린다 (자동 전진)
  → 안개 속에서 좀비·장애물 발견
  → 판단: 피할까(좌우 이동) / 쏠까(탄약 소모)
     (장애물을 피하다 좀비 동선과 겹치는 순간이 생긴다)
  → 낙하산 보급을 주워 탄약 확보
  → 잡히면 칼로 한 번은 탈출 / 두 번째는 사망
  → 목표 거리 도달 → 탈출 성공
  → 결과에서 미션 달성 확인 → 남은 미션을 위해 다시 도전
```

### 3.3 승리·패배 조건
| 구분 | 조건 |
|---|---|
| 승리 | 목표 거리(초기값 1,000m)를 달려 **탈출 지점**(요새 정문, 남은 거리 0m)에 도착 |
| 패배 | 칼이 없는 상태에서 좀비에게 잡힘 → 물려서 사망 |
| 미션 | 승리와 별개로 스테이지 미션 3개의 달성 여부를 판정한다 (4.10). 미션을 못 해도 탈출하면 클리어다 |
