## 패키지·구성품 계약

아래는 팀 main에 맞추는 **계약 버전 2**다. 기존 Cloud 배포본은 버전 1이며 이번 코드 통합만으로 서버가 바뀌지 않는다.

| 상품 ID | 이름 | 서버 가격 | 지급 구성품 |
|---|---|---:|---|
| `pack_survival_kit` | 생존 키트 | 1,100원 | `knife_plus:1`, `ammo_start_pack:1`, `flare_supply:1`, `adrenaline:1` |
| `pack_one_more` | 한 번 더 패키지 | 3,300원 | `revive:1`, `frenzy_30:1`, `bonfire:1` |

- 인벤토리는 패키지 ID가 아니라 위 구성품 `item_id`와 `quantity`로 읽는다.
- 소모품 수량은 누적하고, `gold_pistol`·`supporter_badge`는 최대 1이다. 이전 `golden_pistol_skin` 등 보유 ID는 조회 별칭으로 호환하며 기존 행을 지우지 않는다.
- 새 주문에 계약 버전을 남겨 기존 버전 1 대기 주문은 주문 당시 구성으로 지급하고 새 버전 2 주문만 팀의 새 구성을 사용한다.
- 신규 판매는 패키지 3종만 허용한다. 기존 `ammo_start_pack`·`supporter_badge` 주문/구매/보유 ID는 보존하고 기존 대기 주문 승인 경로는 유지한다.
- 상점·상품 제안에는 “테스트 결제입니다. 실제 돈이 나가지 않습니다”를 표시한다.

## 테스트 근거

이 절의 수치는 현재 스냅샷을 공유하기 위해 실제 실행한 기록이다. 모의 검증·실서버 동작·출시 승인은 구분한다.

**팀 main 통합 후 부모 재검증:** Godot **37개 파일 모두 exit 0**, 백엔드 **100 passed / 0 failed**, 주문/승인 Edge 진입점 type check 통과. Godot 스크립트/파싱 오류 0, 최신 팀 카드 이미지 3개와 앱 복사본의 해시 일치를 확인했다. 종료 리소스 경고는 장면 접점·ESC·모바일 설정 통합·서비스 부활 테스트에 남아 있으며, 테스트 통과와 별도로 관리한다. 아래 수치는 이전 스냅샷의 검증 이력이다.

- 백엔드 오프라인: **94 passed / 0 failed**. 모의 제공자·SQL 구조/레시피 및 검증 SQL의 질문 맥락 인자 회귀를 포함한다. 검증 SQL의 일반 질문에 `{}`가 아닌 `NULL`을 전달하도록 보정했고, 실제 DB 쓰기 검증은 하지 않았다.
- Godot 전체 안전한 로컬 회귀: **32개 파일 모두 exit 0**. 이후 게시 전 계정 경계 수정 후 영향을 받는 **8개 파일을 별도로 재실행해 모두 exit 0** 확인했다. 테스트별 저장 경로를 격리하고 Cloud 검증 스크립트는 실행하지 않았다.
- 계정 경계 보정: 로그아웃/오프라인 게스트 저장의 성공 결과를 확인한 뒤에만 화면을 전환한다. 실패는 오류로 남긴다. 최근 플레이 맥락은 현재 계정 소유자에 연결해 다른 계정의 버그 제보에 섞이지 않게 했다.
- Windows 온라인 export: exit 0. 실제 EXE 안의 리소스 팩에서 `ONLINE_EXPORTED_PACK: PASS` 확인. 이 검사는 인증/결제/LLM 요청을 하지 않는다.
- 한글 입력 검사: `SUPPORT_COMMITTED_UNICODE: PASS`, **`NATIVE_KOREAN_IME: NOT_TESTED`**. 프로그램으로 완성된 문자를 넣은 결과이지 Windows 한글 조합 입력 성공 증거가 아니다.
- Android Kotlin: 현재 컴파일된 클래스의 직접 JUnit **4개 통과**, offline `assembleDebug` exit 0. AAR **21,524바이트**, SHA-256 `be494c6e8e2baeea9c5fc9ff1064800ef653d2af217f23c9cca8a941fdb546bd`; 빌드 출력/배치본 해시 일치 및 `PaymentAttemptState`·`isExactAmount` 포함 확인. APK는 빌드하지 않았다. 복합 Gradle 명령의 `writeUnitTestClasspath` variant ambiguity 실패는 별도로 기록한다.
- 통과 판정과 별개로 종료 리소스 경고가 남는다: 장면 접점 테스트의 ObjectDB 158개/리소스 8개, 실제게임 ESC 테스트의 4개/2개. 반복 플레이의 누적 영향과 원인은 후속 확인 대상이다.

## 로컬 실행

1. Godot 4.7.2로 `godot/project.godot`을 연다. 최초 import가 필요하다.
2. 온라인 연결이 필요하면 `godot/config/서비스_공개설정_예시.json`을 `서비스_공개설정.json`으로 복사한다.
3. 승인된 Supabase URL과 **publishable 공개 키**만 클라이언트 설정에 입력한다. 서버 `service_role`, OpenAI 키, Toss 시크릿 키는 앱에 넣지 않는다. 실제 접속 설정 파일은 Git 제외다.
4. `support_multiturn_enabled`·`package_catalog_ready`는 해당 서버 마이그레이션/함수 반영을 확인한 경우에만 true로 설정한다. 새 상품 계약은 `package_catalog_version: 2`도 필요하다. 예시 파일의 준비 플래그는 안전한 기본값 false이며 실제 접속 파일은 이번 통합에서 변경하지 않는다.
5. 기본 진입 장면은 `res://scenes/ui/서비스_진입.tscn`이다. 테스트 서버를 건드리지 않는 실행이 필요하면 엔진 사용자 인자 `--offline-test`를 사용한다.

예시 명령에서 `godot`은 팀 PC에 설치한 해당 버전 엔진 실행 파일을 뜻한다.

```text
godot --path godot -- --offline-test
godot --headless --path godot --script res://tests/게임_전체흐름_테스트.gd
```

- `Windows 사람 테스트` preset은 서버에 접속하지 않는 오프라인용이다.
- `Windows 온라인 테스트` preset은 실제 공개 설정 JSON을 포함하므로 빌드 전 대상 프로젝트를 확인한다.
- Windows 결제 버튼이 막힌 것은 Android SDK 전용 경계를 유지한 것이다. **PC에서 결제 승인까지 완료됐다고 해석하지 않는다.**
- Android SDK 결제는 별도 테스트 클라이언트 키, 최신 AAR·APK, 기기에서의 실제 동작 확인이 필요하다.

## 남은 문제와 다음 작업

### 다음 구현: 문서 기반 게임 안내

사용자가 **게임 지식 문서를 LLM에 전달하고 그 문서에 근거해 답하는 방식**을 선택했다. 이번 스냅샷 게시가 먼저이며, 아래 변경은 **아직 구현하지 않았다.**

- 채팅창을 새로 열면 과거 기록을 자동 복원하지 않고 고정 인사말로 시작한다. 같은 창 안에서만 대화 맥락을 유지한다. 과거 DB 기록은 임의 삭제하지 않는다.
- 일반 게임 안내, 게임 외 질문, 정보 부족, 모델 호출 오류를 구분한다. 모두 “팀에 전달했어요”로 처리하지 않는다.
- **버그 제보 버튼으로 명시적으로 보낸 내용만 CS 접수**로 처리한다. DB 저장 성공 후 접수됐다고 알린다.
- 팀이 버그 제보 본문·기기 정보·최근 플레이·처리 상태를 함께 확인할 수 있도록 관리자 조회를 개선한다. 현재 관리자 보기는 본문이 없어 관련 메시지 테이블을 따로 읽어야 한다.
- 영구 앱 관리자 계정 지정·권한 변경은 별도 소유자 확인이 필요하다. Supabase Studio 프로젝트 권한과 게임 관리자 역할은 다르다.
