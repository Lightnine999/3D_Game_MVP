## 🎮 게임 소개

### 이렇게 플레이해요
1. **스테이지 카드**에서 이번 판의 미션 3개를 확인하고 출발해요.
2. 캐릭터는 **자동으로 앞으로 달려요.** 좌우로 움직여 좀비와 장애물을 피해요.
3. 권총은 들고 있지만 **총알은 0발.** 하늘에서 낙하산으로 떨어지는 보급 상자를 주워야 쏠 수 있어요.
4. 좀비에게 잡히면 **칼로 딱 한 번** 뿌리칠 수 있어요. 두 번째로 잡히면 끝이에요.
5. 1,000m를 달려 **탈출 트럭**에 도착하면 클리어!

### 핵심 재미
| 요소 | 내용 |
|---|---|
| 🌫️ 안개 속 긴장감 | 시야 30-40m의 밤 들판에서 좀비가 갑자기 모습을 드러내요 |
| 🔫 쏠까, 피할까 | 총알이 귀해서 매 순간 판단이 필요해요 |
| 🧟 좀비 4종 | 느린 **워커**, 옆에서 달려드는 **러너**, 총알 4발을 버티는 **탱커**, 풀숲에 숨은 **매복** |
| 🚧 장애물 | 폐차·드럼통·쓰레기 더미에 부딪히면 비틀거리며 느려지고, 그 사이 좀비가 다가와요 |
| ⭐ 스테이지 미션 | 생존 / 좀비 15마리 처치 / 헛간을 통과해 달리기 — 남은 미션이 "한 판 더"를 부르죠 |
| 🏞️ 와이드 화면 | 폰 화면이 넓을수록 좌우가 더 보여서, 광활한 들판을 달리는 느낌을 줘요 |

### 게임 밖 기능
| 기능 | 내용 |
|---|---|
| 👤 회원가입·회원 관리 | 처음엔 게스트로 바로 플레이하고, 이메일로 가입하면 기록과 구매 내역이 그대로 이어져요. 닉네임 변경·비밀번호 재설정·탈퇴도 돼요 |
| 💳 테스트 결제 | 웹·앱 모두 토스페이먼츠 **테스트 결제** (실제 돈이 나가지 않아요) |
| 💬 문의·제보 채팅 | 게임 안에서 질문하면 AI(OpenAI)가 먼저 답하고, 버그 제보에는 기기·게임 정보가 자동으로 붙어요 |
| 🛡️ 관리자 | 회원·구매·문의 현황을 보고 문의에 답해요 (Supabase 관리 화면 기반) |
| 🧪 테스트 모드 | 결제는 테스트 키로만 동작하고, 개발·관리자용 테스트 패널(무적, 거리 이동, 탄약 지급, FPS 표시)이 있어요 |

## 🛠️ 기술 스택

| 영역 | 도구 |
|---|---|
| 게임 엔진 | Godot 4 (GDScript, Mobile 렌더러) |
| 콘셉트 아트 | OpenAI 이미지 생성 |
| 배경·소품·장애물 | Blender 5.2 — **화면 없이 Python 스크립트로 생성** |
| 좀비 캐릭터·모션 | Mixamo |
| 무기·사운드 | CC0 무료 에셋 |
| 백엔드 | Supabase (게스트·이메일 로그인, 구매 기록, 채팅 저장, Edge Functions) |
| 결제 (마감 범위) | 토스페이먼츠 **테스트 결제** — 웹·앱 공통 결제 페이지 |
| 결제 (Play 출시 버전) | 앱은 Google Play Billing으로 교체 (마감 이후) |
| 문의·제보 채팅 | OpenAI API (서버에서만 호출) — 콘셉트 아트와 같은 OpenAI 계정, 키는 따로 |
| 웹 배포 | Vercel (웹 체험판 + 결제 페이지) |

**바이브 코딩 방식**: 모델·씬·코드가 모두 텍스트 파일이라, Claude가 만들고 명령줄로 실행하고 렌더 이미지·스크린샷으로 결과를 확인합니다. 사람은 Blender나 Godot 에디터를 열지 않아도 됩니다.

```
OpenAI 콘셉트 이미지 → Blender 스크립트 / Mixamo → 자동 검사 → .glb
  → Godot 게임 → 자동 테스트 → Android .aab → Google Play
```

자세한 구조와 결정 이유는 [TECH_SPEC.md](DevelopDoc/TECH_SPEC.md)에 있습니다.

## 🏭 작업 공정

**3개의 생산 라인이 동시에 돌아가고, 하루 두 번 한 자리에 모여 조립해 보는 공장**이에요.

```
출발 준비 (9/29 오전)         3일 개발 (9/29 - 10/1)                           마감
 공통 뼈대(M0)          A 라인: 보이는 세계 ───┐
 연결 규칙(TECH_SPEC 13.3) ──→  B 라인: 돌아가는 게임 ─┼─→ 하루 2번 조립 (M1 - M6) ──→ 🔒 10/1 24:00 코드 동결
 GitHub + 팀 합류       C 라인: 게임 밖 서비스 ┘   머지 → 자동 확인 → 📱 폰 확인    🏁 10/2 10:00 제출
```

- **기다리지 않아요.** B는 A의 회색 가짜 모델로, C는 B의 가짜 게임 신호로 먼저 만들어요. 진짜가 오면 **같은 이름으로 갈아 끼우기만** 해요 ([TECH_SPEC 13.3](DevelopDoc/TECH_SPEC.md)).
- **자주 합쳐요.** 점심·저녁마다 세 브랜치를 `main`에 머지하고 폰에서 확인해요. 충돌은 작을 때 풀어요.
- **기능 하나 = 한 사람.** 한 기능의 장면·스크립트·DB 표·서버 함수를 한 사람이 끝까지 맡아요. 공동 파일도 주인이 한 명씩 있어요.

## 🚀 실행 방법

> 아직 개발 전이라 실행할 수 있는 코드가 없습니다. 아래 명령은 개발 후 제공될 **예정**입니다 (TECH_SPEC 5.1, 9.1).

```bash
./pipeline.sh assets          # 모든 3D 에셋 생성 → 검사 → Godot 가져오기
./pipeline.sh install-device  # USB로 연결한 안드로이드 폰에 설치
./pipeline.sh build-android   # 서명된 APK (마감 제출·직접 배포용) + .aab (Play 업로드용)
./pipeline.sh build-web       # 웹 체험판 빌드
```

필요한 도구 (2026-09-28 설치 확인)

| 도구 | 버전 |
|---|---|
| Godot + 내보내기 템플릿 | 4.7.2 stable |
| Blender | 5.2.2 LTS |
| OpenJDK | 17 |
| Android SDK | build-tools 35.0.1, platforms android-35, NDK 28.1.13356709, CMake 3.10.2.4988404 |
| Supabase CLI / Vercel CLI | 2.118.0 / 59.16.0 |

환경변수 `JAVA_HOME`(OpenJDK 17)과 `ANDROID_HOME`(Android SDK 경로)이 설정되어 있어야 합니다.
